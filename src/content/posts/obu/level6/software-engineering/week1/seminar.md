## Initial Statement of Requirements

With the advent of mobile and cloud computing technologies, it is perceived that the traditional restaurant table booking can be revolutionised by developing a mobile application that links to a back-end cloud computing system delivering functionality in the form of Software-as-a-Service (SaaS). In other words, the system should enable restaurants to subscript to the services and customise the system according to the restaurant’s specific data, which including the menu, number of tables, opening hours, locations, etc. The system will host multiple restaurants and enable users to book tables from these restaurants.

The CloudSoft [+CloudSoft] Ltd thus decided to develop such a system to realise advanced functions of restaurant table booking. It is perceived to consist of three parts:

[+CloudSoft]: This is a fictional company specializes in the development of computer application systems.

(a) a mobile app running on smart phones for restaurant customers to book tables at a restaurant of their choice, and even to order food from the menu;  

(b) a web interface running on desktop or tablet computers for restaurant managers to setup the data of the restaurant and its staffs to operate the table allocation, services of food, accept customer’s payments for the bills, etc.  

(c) a back-end software system running on a server for system operators to perform operation across restaurants and to store information.

The following are the key features that the system should realise.

The system should realise quick dynamic update the state of the restaurants, including information about the availability tables/seats in real time, availability of the food, etc. Dynamic update of information has been recognised as one of the killer features of this system that distinguishes it from static web sites of restaurants.

Another killer feature of the system is that it should provide those services across individual restaurants, such as the favourable dishes and menus over all restaurants, the discount vouches and royalty points for use at any restaurants on this system, etc. This relies on collecting a lot of data from a large number of participating restaurants.

It is important to connect all components together to make the activities of searching, booking, ordering, paying bill, and commenting on the services and food of a restaurant a continuous effortless and seamless process. For example, viewing a favourable menu or dish should be linked to pre-order/order the dish or menu with one click of button. The process of different types of users must be integrated seamlessly, too.

The system should provide apps for restaurant customer users running on various mobile phone/device platforms with graphic user interface. It should also provide user friendly HCI for Restaurant Managers, Service Staffs and System Operators as well. It should enable pictures of the food be associated to the menus, pictures of the rooms and surrounding environment be uploaded to the website, etc.

## Week 1 Practical Exercise

Read the Case Study 1 for Practical Classes, i.e. the _Mobile Restaurant Booking System_, work in a group of 4-5 students, and answer the following questions.

1. Which type of software system in Lehman’s classification the _Mobile Restaurant Booking System_ belongs to? And why?
2. For each type of software uncertainty in Lehman theory, what specific presentations of the uncertainty are most likely to occur in the development and operation of the _Mobile Restaurant Booking System_?
3. Which type of uncertainty will dominant the development and evolution of the system? And why?
4. For each of the software process models taught in the lecture, which specific uncertainty can be nicely dealt with? And why?
5. For each software process model taught in the lecture, which uncertainty may have difficulty and/or be costly to prevent and/or to minimize the impact when it occurs? And why?
6. How do you compare these process models? And which one you would select to use to develop the system?
7. With the process model that you selected to answer question 6, what is your risk management plan to prevent the uncertainty to occur, and/or to minimise the impact of the risk when it occurs?
8. “_Time to market_” has been widely recognised as an important factor for the success of a computer application. Can you explain this phenomenon in Lehman theory of software evolution?
